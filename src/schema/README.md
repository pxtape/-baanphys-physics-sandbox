# Scene v1 domain-validation API (M1-02)

```ts
import { parseSceneJson, validateScene } from './index';

const result = parseSceneJson(jsonText); // untrusted JSON text
// validateScene(candidate) accepts plain in-memory JSON and makes a detached copy.
if (result.ok) {
  const authoredScene = result.scene; // deeply readonly and frozen, original IDs
  // result.executionReady is always false in M1-02; do not run or save blindly.
  console.log(authoredScene.title);
} else {
  // No partial scene is returned on failure.
  for (const issue of result.diagnostics) {
    console.log(issue.code, issue.path, issue.message, issue.suggestion);
  }
}
```

This task adds a reusable domain boundary, not UI commands, a store, file dialogs,
canvas, physics adapter or persistence. Use the same Scene v1 JSON representation
throughout. To propose an authored edit later, construct a candidate without
mutating the old document and validate it; replace state only on success. No IDs,
vertices, mass models or settings are automatically regenerated/recentred/coerced.

## Checks, in order

1. **Input:** 2 MiB UTF-8, 32 nested containers, decoded duplicate JSON names,
   standard JSON grammar and finite numbers. Collection caps are read from the
   existing schema (100 bodies/constraints, 200 forces, 20 meters, 50 controls,
   128 polygon vertices). No graph buffers are allocated. Raw JSON text is the
   untrusted import API. A future file/browser layer should also bound the file
   before reading/decoding it.
2. **Structure:** the bundled Draft 2020-12 schema, full calendar-aware RFC3339
   date-time assertion and bare hyphenated UUID assertion. No missing defaults,
   coercion or removal of unknown properties. JSON-pointer paths escape `~` and
   `/`. Unknown future versions reject; no implicit migration exists.
3. **Semantics:** global entity UUID uniqueness (case-insensitive comparison,
   original strings preserved), correct body references, dynamic constraint/force
   targets, no same-body/static-only constraints, zero static velocities,
   material ordering, finite positive uniform-lamina area/mass/inertia, and
   polygon simplicity/CCW/strict convexity/edge/area/centroid invariants from
   SCENE_FORMAT.md. There is no silent convex hull/decomposition/recentring.
4. **Controls/identity:** unique target parameters, ordered bounded control
   intervals, valid step/default/mass-mode/range, distinct simulation/revision
   IDs, first/later parent rules, no self-parent, UTC Z timestamps and exact
   fractional timestamp ordering. Repository lineage/ownership cannot be proved
   from a file and is explicitly warned, not invented.
5. **Result:** errors have stable codes, stage, severity, RFC6901 path, message
   and corrective suggestion. Reports cap at 100 diagnostics, with an explicit
   truncation diagnostic if needed. Successful scene/result/diagnostics are frozen
   after validation. Caller objects are never frozen or mutated; no UI/runtime
   data or derived physical properties are inserted into JSON.

## Valid document is not qualified execution

A valid document returns `executionReady: false` and `EXECUTION_NOT_VALIDATED`.
There is no production profile registry or installed adapter in M1-02. In M1-03,
a trusted adapter must independently gate exact engine/adapter/profile versions,
fixed settings, tested physical envelope, friction mapping, vertex counts and
**every allowed student parameter range** before execution. For example, Scene v1
can describe 128 convex vertices, but that does not qualify a >8-vertex Planck
fixture. Unequal static/dynamic coefficients can be valid authored data but are
not supported by the planned initial Planck profile. The existing unqualified
Matter example remains valid for inspection and is never silently converted.

`REVISION_HISTORY_NOT_VALIDATED` on saved documents likewise requires M1-07 to
check parent existence, same-simulation lineage, revision sequence, identity
conflicts, ownership and expected head before persistence. Initial overlaps are
not a document-format error here; benchmark/runtime collision acceptance is a
separate gate. No new physical accuracy claim or benchmark tolerance is added.

## One contract, generated types and static validation

`schemas/scene-v1.schema.json` stays unchanged and is the source of truth:

```sh
npm run generate:scene  # regenerate the checked-in types + standalone validator
npm run check:generated # detect drift; also runs before typecheck and build
npm test
```

- `src/domain/scene-v1.generated.ts` is generated by json-schema-to-typescript.
  `SceneDocument` in domain/scene.ts is its deep-readonly projection, not another
  runtime scene format. Numeric/format/semantic invariants still need validation;
  a TypeScript annotation alone is not proof of physical validity.
- The development-only generator compiles **only the trusted checked-in schema**
  with Ajv 2020 and format assertions, then emits a static ESM function and type
  declaration. No imported `$schema`/`$ref` chooses a schema, compiler or URL.
- The runtime imports static validation plus ajv-formats' non-compiling format
  functions. It never imports the Ajv compiler or uses eval/new Function. The
  inlined Ajv Unicode helper retains its MIT notice. Generated JS is not manually
  linted; deterministic regeneration, tests and browser bundling verify it.
- Tests run the static validator under Node's
  `--disallow-code-generation-from-strings`, and bundle/execute the complete API
  as a browser-target ESM library without Node imports or the Ajv compiler.

The in-memory API rejects cycles, getters, functions/toJSON, class instances,
non-enumerable/symbol members, sparse/named arrays and nonfinite values. JavaScript
Proxy traps cannot be made inert by an object-inspection API; arbitrary host
objects are outside its contract. Use parseSceneJson for untrusted external input.
Real Safari/iPad/UI testing is not claimed by the browser-target bundle test.

### Timestamp compatibility and ordering

Scene v1 keeps the existing canonical schema and pinned ajv-formats 3.0.1 full
`date-time` assertion. Its parser accepts a four-digit Gregorian date, one `T`,
`t` or ECMAScript `\s` separator, two-digit hour/minute/second fields and an
optional decimal fraction with one or more digits. Schema format checking also
accepts `z`/`Z` and signed offsets (`±HH`, `±HHMM`, `±HH:MM`); existing scene
semantics require uppercase `Z`, so offsets and lowercase `z` remain rejected.
Repeated separators, missing zones and invalid calendar/time fields fail format
validation. Accepted leap-second representations remain accepted; the format
library does not certify historical leap-second dates.

Ordering now compares parsed numeric UTC calendar fields and exact decimal
fractions, independently of the separator. Fractions are zero-padded for
comparison only, never converted to floating point or truncated to milliseconds.
Leap second 60 sorts after second 59 and before the following date. Year 0000
through 9999 retain the format validator's existing behavior. Authored strings
are preserved verbatim. No format restriction, schema migration, host Date
parsing, timezone conversion or network lookup is introduced.

`timestamps.test.ts` enumerates all 25 ECMAScript whitespace characters plus T/t,
checks all 729 separator pairs in both ordering directions and equality, and
runs every check through both in-memory and JSON-text entry points. Future
format-library changes must retain or explicitly review this compatibility.
